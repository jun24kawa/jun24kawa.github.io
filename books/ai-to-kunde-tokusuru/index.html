第1章　まずは使ってみよう

　最近、AI が話題になっていて、なんだかすごいことができるそうだ、ということは聞いている。でも、何がすごいのか、何ができるのかが、見当つかない。でも、その AI を使えないと、時代に置いていかれそうで怖い。逆に、AI を使いこなせたら、仕事に有利になるらしい。どう始めたらいいのか、分からない。

　そんなあなたのための本が、本書です。

　「AI を使いこなす」には、二段階あります。第一段階は、「とりあえず使える段階」です。これは、笑っちゃうほど簡単です。信じられないと思いますが、AI に関する専門的な知識は、まったく必要ありません。理系的な専門知識も、まったく必要ありません。皆さんは、グーグル検索を使っていますよね。その皆さんだったら、「とりあえず使える段階」は、一週間で到達できます。

　この段階になると、皆さんは、あることに気づきます。「こんな簡単で、誰でもできることだったら、遅かれ早かれ、みんなが使えるようになる。その中で、自分が AI の使いこなしで一頭抜きん出るためには、どうしたらいいのか?」と、思い始めると思います。

　ご安心ください。そうなるために、AI に関する専門的な知識は、まったく必要ありません。理系的な専門知識も、まったく必要ありません。実は、本書は、大部分が、その能力を獲得するための本なのです。

　しかし、いきなり、そのレベルの話をしたら、ついていけない人が多いと思います。でも、それは、私もそうでした。長いあいだ、どうしようかなと悩んで、何もしていませんでした。ところが、やり始めたら、本当に簡単で、ビックリしたのです。

　私も、そして皆さんの多くも、いちばん大変な壁は、「やる」と行動することなんです。

　まず、行動しましょう。

先に知っておくこと ── パソコン操作で、つまずきやすいところ

　登録の手順に入る前に、多くの人がつまずくところを、先に書いておきます。ここを知っておくと、途中で「壊れたかな」と不安になりません。

  • パスワードを打っても、画面には「●●●」しか出ないか、何も出ないことがあります。 これは正常です。文字が見えなくても、そのまま最後まで打って、Enter キー（キーボードの右のほう、文字キーのかたまりの右端にある、少し大きなキー）を押してください。
  • コピーして貼り付ける操作が、効かない画面があります。 そのときは、あきらめて、直接キーボードで打ってください。
  • 「¥」と「\」は、同じ文字です。 パソコンによって、見え方が違うだけです。あとでフォルダーの名前や場所を打つときに出てきます。
  • 画面が数十秒、止まったように見えることがあります。 故障ではありません。そのまま待ってください。
  • クレジットカードの番号など、お金に関わる入力は、必ず自分の手でしてください。 AI には、絶対にさせません。

Claude の登録

　本書では、Claude と Claude Code という AI を使います。皆さんの中には、AI に質問を入力して、答えてもらったことがある人がいると思います。あれは、チャット型 AI と呼ばれます。Claude（クロード）は、アンソロピック（Anthropic）社の開発した、チャット型 AI です。そして Claude Code（クロード・コード）とは、その機能を拡張したものです。

　とりあえず、Claude を使えるようにしましょう。Claude は無料で使い始められるサービスなので、ここから始めましょう。Claude の登録方法は、以下のとおりです。

1. ブラウザを開きます。 ブラウザとは、インターネットを見るためのソフトです。Windows なら「Edge」（青い波のマーク）か「Chrome」（赤・黄・緑・青の丸いマーク）。ふだんインターネットを見るときに使っているもので構いません。

2. 画面のいちばん上にある、横長の細い欄に、`claude.ai` と打ちます。 この欄を「アドレス欄」と言います。ページの中ほどにある検索窓と間違えやすいので、いちばん上の、左右いっぱいに横に長い欄を探してください。打ち終わったら、Enter キーを押します。

3. Claude のページが開きます。「Sign up」または「無料で始める」「登録」と書かれたボタンを押します。

  • 「Log in」「ログイン」は、すでに登録した人が入るための入口です。今回は、こちらではありません。

4. 登録のしかたを選びます。二つあります。

  • Google のアカウント（Gmail のアドレスなど）を持っている人：「Google で続ける」「Continue with Google」を押すのが、いちばん簡単です。ふだん Gmail を見るときのパスワードで進めます。新しくパスワードを作る必要がありません。
  • メールアドレスで登録する人：自分のメールアドレスを打って、「続ける」を押します。すると、そのアドレスあてに、Claude から数字（確認コード）の書かれたメールが届きます。一〜二分で届きます。届かないときは、「迷惑メール」のフォルダーも見てください。届いた数字を、画面の欄に打ちます。

5. 名前や、使う目的を聞かれたら、答えます。 ここは、正直に選んで構いません。あとから変えられます。

6. これで、登録は完了です。 画面の下のほうに、文章を打ち込む横長の欄（四角い枠）が出れば、成功です。ここまで、料金はかかりません。

　以上で、登録ができました。

　さて、使い方は、下の四角い枠に、あなたの希望すること、知りたいことを入力してください。ただし、多くの人にとっては、最初に、次の一文を入力することをお勧めします。

> 　今後の私との会話では、専門用語を使わずに、具体的な表現を使ってください。

　なんだか、拍子抜けされたのではないでしょうか。そうです、Claude との会話は、普通の会話でいいんです。これだけで、Claude は今後、あなたとの会話では、専門用語を使わず、具体的な言い方をするようになります。

　さらに、何らかの不満や希望があれば、それを打ち込んでください。「もっと短く答えて」「箇条書きにして」「私は教員なので、その前提で話して」。そうやって、あなたに合った AI に育てていくことができます。この「使いながら、注文を伝えて、育てていく」やり方は、あとで出てくる Claude Code でも、まったく同じです。

　とりあえず、次の二つを、やってみてください。

　一つ。 あなたが、買うかどうか検討している品物について、長所と短所を教えてもらってください。「今、○○という掃除機を買おうか迷っています。長所と短所を、それぞれ三つずつ。私は一人暮らしで、部屋は狭いです」というように、自分の事情も添えると、答えがぐっと具体的になります。

　二つ。 あなたが来週行こうとしている町での、小旅行の計画を聞いてください。このときは、日時の縛り（「土曜の朝に出て、夕方には帰りたい」）や、絶対に行きたいところ（「この美術館だけは外せない」）を、先に伝えてください。

　ほかにも、たとえば、こんなことが聞けます。

1. 献立の相談 ──「冷蔵庫に、卵、キャベツ、豚こま肉、絹ごし豆腐があります。これで作れる晩ごはんを、作り方つきで三つ教えて」

2. 難しい文章のかみ砕き ──「この保険の説明の文章を貼ります。中学生にも分かる言葉で、要点を五つにまとめて」（役所からの通知、契約書、家電の説明書なども、同じように頼めます）

3. 手紙・メールの下書き ──「入院中にお見舞いをくれた上司へ、退院後のお礼のメールを書きたい。堅すぎず、三行くらいで」

4. 段取りの相談 ──「土曜の午前中に、クリーニングの受け取り、銀行、スーパー、実家への立ち寄りを済ませたい。効率のいい順番と、だいたいの時間配分を教えて」

5. お金の計算 ──「毎月二万円を、年利三パーセントで二十年間、積み立てたら、いくらになりますか。計算の途中も見せて」

6. 言葉の意味 ──「『解像度が高い』という言い方を、最近よく聞きます。どういう意味で、どんな場面で使うのか、例文つきで教えて」

7. もやもやの整理 ──「同僚に『まあ、あなたらしいね』と言われて、もやっとしました。相手はどういうつもりだったと考えられますか。私は、どう受け止めればよかったですか」

8. 買い物の下調べ ──「一人暮らし向けの、二万円以下のオーブントースターを選ぶとき、見るべき点は何ですか。よくある失敗も教えて」

9. 初めてのことの手順 ──「来月、初めて確定申告をします。何を、いつまでに、どういう順で準備すればいいか、初めての人向けに教えて」

10. ニュースの整理 ──「（話題になっている出来事）について、何が問題になっているのか、経緯を時系列で、十行くらいで。むずかしい用語には、かっこ書きで説明を付けて」

　もし、Claude にどんな質問に応えてくれるかを知りたければ、「Claude に対する代表的な質問を三十ぐらい教えて下さい」と打ち込んで下さい。「え！？こんなことにも対応してくれるの」と驚くかもしれません。なお、繰り返しですが、Claude の返事に満足できなければ、その不満・希望を何度でも書き続ければ、Claude の返事はあなたの求めるものに近づきます。

　このような質問を、三日から一週間ぐらい、やってください。もし、あなたが、次のことを理解できたら、次の段階です。

1. まるで人と話しているようにしていれば、AI は分かってくれて、教えてくれる。

2. これだったら、私でも使える。

3. 人工知能って、今でも十分にすごいけど、もっとすごいことができるの? 知りたい。

Claude Code の登録

　もっとすごい AI を使いたい、というあなたに、判断してほしいことがあります。

　次の Claude Code を使うには、月あたり約三千円の会費が必要です（2026年9月現在。プランや時期によって変わります）。ただし、いつでも解約できます。だから、Claude Code ががっかりだったら、解約すればいい。そうすれば、被害は、約三千円だけです。

　では、Claude と Claude Code の違いは、何でしょうか。ひとことで言うと、前者は「教えてくれる」AI、後者は「やってくれる」AI です。

　たとえば、Claude Code ができることを、いくつか挙げましょう。

　あなたのパソコンにつながっているプリンターの調子が悪い場合は、「プリンターの調子が悪いから、なんとかならない?」と入力すれば、プリンターに関わる情報を自分で集めて、解決してくれます。解決できなくても、原因の切り分けをして、あなたが何をすればいいか、その手順を提案してくれます。

　ほかにも、たとえば、こんなことができます。

1. 書類・写真の整理 ──「このフォルダーの中の写真を、撮影した年月ごとのフォルダーに分けて。ファイル名も『2025-04_旅行』のように付け直して」

2. Excel（エクセル）の作り直し ──「この売上表を、月ごとの合計と、伸びている商品・落ちている商品がひと目で分かる形に作り直して」

3. たくさんの資料の要点まとめ ──「このフォルダーの PDF を全部読んで、それぞれの要点と、共通して出てくる論点を、一覧表にして」

4. 表記のゆれを直す ──「このフォルダーの文書で、『お問合せ』と『お問い合わせ』が混ざっている。全部そろえて、直した場所を一覧で報告して」

5. 調べもの＋資料作り ──「（テーマ）について、信頼できる情報を調べて、A4 一枚の説明資料にして、`説明.docx` という名前で保存して」

6. パソコンの不調 ──「起動に五分かかる。原因を調べて、安全な範囲で速くして。何を変えたか、記録も残して」

7. 定期作業の仕組み化 ──「毎月一日に、このパソコンの健康診断をして、結果をメールで送ってくれる仕組みを作って」

8. 録音の文字起こし ──「この会議の録音（`会議.m4a`）を文字起こしして、発言者ごとに分けて、要点も付けて」（専用の道具が要る場合は、その入れ方から教えてくれます）

9. 簡単な道具作り ──「毎日の体重を記録して、グラフで見られる、簡単な道具を作って」。プログラミングの知識は要りません。

10. 要らないファイル探し ──「このフォルダーで、中身が重複しているファイルや、もう使っていない古いファイルを探して。『ゴミ箱』というフォルダーを作って、そこに移して。消さないで」

　皆さんは正直、「そんなことできるの?」と思っていると思います。私も、はじめは、そう思いました。やってみれば、分かります。約三千円で、その世界へ入れるとしたら、入りませんか。

　入りたい人に、Claude Code の登録方法を、以下に伝えます。

アップグレードの方法

　最初に、大事なアドバイスをします。これから、Claude Code から指示を受けて、コンピューターを操作していきます。ところが、Claude Code が示したとおりの画面にならなかったら、どうしますか。もう、分かっていますよね。その画面が出ないことを、Claude に聞けばいいのです。きっと Claude は、「どんな画面が見えていますか」と聞き返してくるはずです。そうしたら、具体的に教えてあげてください。

　やることは、大きく二つです。A. 有料プランに切り替える。B. パソコン用のアプリを入れて、「Code」を開く。

　A　有料プランに切り替える

1. さきほど登録した Claude の画面を開きます。

2. 画面の隅（多くは左下、または右下）にある、自分の名前か歯車のマークを押して、メニューを開きます。

3. その中の「Upgrade」「アップグレード」「プランをアップグレード」を選びます。

4. プランが、何段階か出ます。上のプランほど、たくさん使えます。まずは、真ん中あたりのプランで十分です。金額を、画面でよく確かめてください。

5. 支払い方法として、クレジットカードを登録します。

  • このカード番号の入力は、必ず、あなた自身の手でしてください。 金額と、月ごとの支払いであることを、もう一度確かめてから進めます。

　B　アプリを入れて、「Code」を開く

1. ブラウザのアドレス欄に、`claude.ai/download` と打って、Enter キーを押します。

2. 「Windows」版のダウンロードボタンを押します。

3. ダウンロードが終わると、画面の下や右上に、ダウンロードしたファイル（名前に `Claude` が入っています）が出ます。それをダブルクリックします。

4. ここで、確認の画面が出ます。「このアプリがデバイスに変更を加えることを許可しますか?」と表示され、ボタンは「はい」と「いいえ」です。「はい」を押してください。 これは、アプリをパソコンに入れるための、ふつうの確認です。押して問題ありません。

5. しばらくすると、Claude のアプリが開きます。さきほど登録したアカウント（Google か、メール）で、サインインします。

6. アプリの画面のどこかに、「Code」という切り替え（タブ）があります。それを押します。これが Claude Code です。

  • ※パソコンに詳しい人向けに、黒い画面（ターミナル）から入れる方法もありますが、ここでは説明しません。アプリの方法で十分です。
  • ※プランによって、使える量が違います。たくさん使うと、「今日はここまで」という表示が出て、時間をおくと、また使えるようになります。

　これで、Claude Code が使えるようになりました。

　では、使い始めましょう。大事なことは、さきほど Claude のところで書いたとおりです。使っているうちに、希望があったり、不満があったりしたら、それを Claude Code に、普通の言葉で伝えてください。そうすれば、Claude Code は、あなたに合わせて成長します。

使うモデルを確認する

　Claude には、賢さと値段の違う、いくつかの「モデル」（頭脳の種類）があります。主なものは三つです。

  • Opus（オーパス） ── いちばん賢く、いちばん高い。
  • Sonnet（ソネット） ── 賢さと値段のバランスがいい。
  • Haiku（ハイク） ── いちばん速く、いちばん安い。簡単な作業向き。

　この本で説明していることは、Sonnet を使う前提で書いています。値段のわりに賢く、コストパフォーマンスがいちばんいいからです。

　Claude Code の画面のどこかに、いま使っているモデルの名前が出ています（画面の下のほうか、設定のメニューの中）。Sonnet になっていなければ、そこを押して、Sonnet に切り替えてください。

活動場所となるフォルダーを作る

　Claude と違って、Claude Code には、「どこで作業するか」という場所を、最初に決めます。それが、フォルダーです。Claude Code は、指定したフォルダーの中だけを見て、その中のファイルだけを読み書きします。外のファイルには、勝手に手を出しません。安全のための仕組みです。だから、Claude Code に任せたいファイルは、このフォルダーの中に入れておきます。

1. デスクトップ（パソコンを起動したときの、いちばん後ろの画面）の、何もないところで、右クリックします。

2. 出てきたメニューから、「新規作成」→「フォルダー」を選びます。

3. 新しいフォルダーができるので、名前を付けます。ここでは「AIのしごと場」としておきます。

4. Claude Code の画面で、「フォルダーを開く」「Open folder」という案内を押し、いま作った「AIのしごと場」を選びます。

5. ここで、確認の画面が出ます。「このワークスペースを信頼しますか?」と表示され、「信頼する（Trust）」と「信頼しない」のボタンがあります。自分で作った、中身の分かるフォルダーなので、「信頼する」を押してください。 これは、知らないフォルダーを勝手に動かさないための、安全確認です。

6. これで、準備完了です。下の入力欄に、してほしいことを、普通の日本語で書きます。

　作業の途中で、確認の画面が、たびたび出ます。「このファイルを書き換えてよいですか」「このコマンドを実行してよいですか」といったものです。ボタンは、たいてい「許可（Allow）」と「拒否（Deny）」です。書かれている内容を読んで、心当たりがあって問題なければ「許可」。少しでも不安なら「拒否」を押して、「なぜ、これが必要なの?」と聞いてください。

　なお、調べものや下書きのような、あとで元に戻せる作業は、いちいち聞かずに進みます。ファイルを消す・上書きする・外に送るといった、取り返しのつかない作業は、必ず先に聞いてきます。

何を準備して、どう頼むか ── 五つの例

　さきほど挙げた使い方について、「何を、どこに置いて、どう言えばいいか」を、具体的に書きます。共通するコツは、二つです。

  • 元のファイルは、そのまま残す。 Claude Code に渡すのは、コピーです。作業フォルダーに、コピーを入れます。
  • 「新しい名前で保存して」「元のファイルは変えないで」と、ひとこと添える。 そうすれば、大事な原本が上書きされることは、まずありません。

　例1　Excel の売上表を、作り直してもらう

  • 準備 ── その Excel ファイル（例：`売上.xlsx`）を、作業フォルダー「AIのしごと場」の中に、コピーして入れます。元の `売上.xlsx` は、いつもの場所に、そのまま置いておきます。
  • 指示の例 ──「このフォルダーの `売上.xlsx` を読んで、月ごとの合計を出して、売上が伸びている商品と落ちている商品が分かる表に作り直して。結果は `売上_整理済み.xlsx` という新しい名前で保存して。元のファイルは変えないで」

　例2　たくさんの PDF の要点を、まとめてもらう

  • 準備 ── 読ませたい PDF を全部、作業フォルダーの中に入れます。数が多ければ、その中に「資料」というフォルダーを作って、そこにまとめます。
  • 指示の例 ──「`資料` フォルダーの中の PDF を全部読んで、それぞれの要点を五行でまとめて。そのあと、複数の資料に共通して出てくる話題を、一覧にして。全体を `まとめ.txt` という名前で保存して」

　例3　プリンターなど、機器の不調を見てもらう

  • 準備 ── 特にありません。プリンターの電源は、入れておきます。
  • 指示の例 ──「このパソコンにつないでいるプリンターで、印刷しようとすると『応答なし』と出る。原因を調べて、直せそうなら直して。無理なら、私が何をすればいいか、順番に教えて」

　例4　文書の表記のゆれを、そろえてもらう

  • 準備 ── 直したい文書（Word でも、テキストファイルでも）を、作業フォルダーに入れます。ここでも、コピーを入れて、原本は残します。
  • 指示の例 ──「このフォルダーの中の文書で、『お問合せ』と『お問い合わせ』が混ざっている。全部『お問い合わせ』にそろえて。どのファイルの、どこを直したか、最後に一覧で教えて」

　例5　調べものをして、資料を作ってもらう

  • 準備 ── 不要です。
  • 指示の例 ──「『（調べたいこと）』について、信頼できる情報を調べて、A4 一枚くらいの説明資料にして。むずかしい言葉には、かっこ書きで説明を付けて。`説明.docx` という名前で、このフォルダーに保存して」

　以上のような活動を、二週間程度、やってみてください。

　この段階になると、皆さんは、あることに気づきます。「こんな簡単で、誰でもできることだったら、遅かれ早かれ、みんなが使えるようになる。その中で、自分が AI の使いこなしで一頭抜きん出るためには、どうしたらいいのか?」と、思い始めると思います。

　そうしたら、次の章に進んでいきましょう。

第2章　これからの社会と、AI の居場所

　この本は、AI を仕事に使うことになる人へ向けて書いています。働き始めて間もない人。部下を持つ立場の人。教える立場の人。そして、これから社会に出る中高生。読む人の立場はさまざまですが、話の中身は一つです。だから、まず土台になる絵を描いておきます。社会がどこへ向かっていて、その中で AI が何をする道具なのか。以降の章は、すべてこの章に戻って組み立てます。

規格の時代は、終わりに向かっている

　アルビン・トフラーは『第三の波』で、工業化社会を動かしてきた六つの原則を挙げました。規格化、専門化、同時化、集中化、極大化、中央集権化です（トフラー　第三の波　1980）。かんたんに言うと、規格化＝みんな同じものを同じ形で作ること、専門化＝一人が一つの作業だけを担当すること、同時化＝決まった時間に合わせてみんなが動くこと、集中化＝人や仕事を一か所に集めること、極大化＝大きくすればするほど得だとする考え方、中央集権化＝決める人を一人か少数に絞ること、です。同じ製品を、同じ手順で、同じ時間に、大きな工場に人を集めて作る。学校も会社も、この六つで組まれてきました。決まった時間に集まり、決まった課程を、決まった順で進む。私はそう見ています。

　次の時代（脱工業化社会と呼ばれます）のコードは、その裏返しです。個性化、総合化、非同時化、分散化、適正規模化、地方分権化。かんたんに言うと、個性化＝一人ひとりに合わせること、総合化＝バラバラだったものを一つにまとめること、非同時化＝決まった時間に縛られず、それぞれのタイミングで動くこと、分散化＝人や仕事を、あちこちに散らしておくこと、適正規模化＝大きすぎず小さすぎず、ちょうどいい大きさにすること、地方分権化＝決める人を、中央ではなく、それぞれの現場に近い人にすること、です。

　私はこの軸を、前著で一度使っています。書名は『「一人も見捨てない」は、得です。──教育・投資・防災を貫く一本の戦略』。私が長く唱えてきた「一人も見捨てない」という考え方を、道徳の話としてではなく、損か得かの「得」の話として組み直した本です。多様な人と折り合いをつけるのは、現役のあいだは得だ。ただ、その先がある。安全な土地と経済的な自由を手に入れれば、人は、家族とごく少数で完結した暮らしに戻れる。それを守る手段が、投資（お金）と、防災（土地）だ ── 教育・投資・防災を、一本の線でつないだ本です。市販はせず、下書きを https://jun24kawa.github.io/ で公開しています。この本のことを、以降「損得本」と呼びます。 損得本では、この「裏返しのコード」を、「どこに住み、誰と暮らすか」の話に使いました。いまお読みの本では、同じ軸を、「どう働き、どう学ぶか」の話に使います。

AI は、この切り替えを速める道具

　AI は、規格化された知的作業を肩代わりします。文章を書く。資料を読む。要点をまとめる。調べる。型どおりのプログラムを書く。こうした「手順の決まった頭の仕事」を、AI が引き受けはじめています。

　AI は、この六つを、それぞれ実現する道具でもあります。個性化なら、一人ひとりの文章のクセや好みに合わせて、答え方を変える。総合化なら、バラバラな資料やデータを、AI が一つの文章・一つの表にまとめる。非同時化なら、深夜でも早朝でも、こちらの都合のいい時間に、いつでも動いてくれる。分散化なら、大きな部署に頼らず、一人ひとりが自分の手元で、必要な仕事をこなせる。適正規模化なら、大きな組織を作らなくても、一人と AI で、ちょうどいい大きさの仕事ができる。地方分権化なら、本社に伺いを立てなくても、現場にいる人が、その場で AI に相談して決められる。

　これは印象ではなく、数字で確かめられています。米国で453人の大卒の職業人に、仕事に近い文章作成の課題を与えた実験では、AI を使えた側は、かかった時間が4割減り、出来ばえの評価が2割ほど上がりました（Noy, Zhang　Experimental evidence on the productivity effects of generative artificial intelligence　Science　2023）。ソフトウェア開発でも、95人の開発者を無作為に二つに分けた実験で（最後まで終えたのは70人）、AI を使えた側は5割以上速く仕上げています（Peng ほか　The Impact of AI on Developer Productivity: Evidence from GitHub Copilot　arXiv　2023）。企業3社・4,867人規模の実験でも、片づけた仕事の量が2割以上増えました（Cui ほか　The Effects of Generative AI on High-Skilled Work　Management Science　2025）。

　いくつかの実験が、もう一つ同じ方向を指しています。もともと不慣れな人、経験の浅い人ほど、AI を使ったときの伸び幅が大きい。差が縮む方向に働くのです（少なくとも Noy・Zhang と Cui ほかは、そう報告しています）。ここは後で、この本の宛先の話につながります。

　分業の前提も動きます。かつては小さなチームでやっていた仕事を、一人と AI でこなせるようになる。これは私の見立てですが、根拠は目の前にあります。この本を作っている作業がそうです。私と一つの AI とで、蔵書の取り込み、原稿の校正、公開用サイトの構築を、並行して進めています。数年前なら、何人か雇うか、外に出すかしていた仕事です。

　ここで、疑問に思う方もいるでしょう。AI を動かしているのは、巨大なデータセンターです。規格化・集中化・極大化・中央集権化の、まさに極致に見えます。矛盾していないか、と。

　二つ、お答えします。

　一つ。社会の切り替えは、総入れ替えではありません。狩猟社会が農業社会に変わっても、狩猟という営みそのものは、現代まで残っています。同じように、工業化社会が脱工業化社会に向かっても、工業化社会は併存します。技術が追いついていない部分は、しばらく工業化社会のコードのままで回る ── それは当然のことです。生成 AI 向けの巨大なデータセンターは、まだ立ち上がったばかりの技術です。

　もう一つ。これは、初めて起きる話ではありません。トフラーは『第三の波』で、集中型の巨大発電所を、工業化社会（第二の波）の象徴として描き、太陽光・風力のような分散型のエネルギーを、脱工業化社会（第三の波）の方向として挙げました（トフラー　第三の波　1980）。なぜ、分散に向かうのか。エイモリー・ロビンズとハンター・ロビンズは、集中し、複雑になりすぎたエネルギーシステムほど、事故にも妨害にも、大規模な障害に対して脆くなると論じています（ロビンズ、ロビンズ　Brittle Power: Energy Strategy for National Security　1982）。大きく、複雑になるほど、危険性は増す。データセンターも、効率よく小型化できるようになれば、同じ理屈が当てはまり、集中はゆるみます。根拠のない期待ではなく、すでに指摘されてきた理屈の延長です。

　そして、見るべきは、企業やインフラの集中だけではありません。個人が、どこで、誰の判断で働くかという軸では、分散が進んでいます。リモートワークの発達で、地方に住んで働く人が増えました。私自身、上越に住み始めた当初、研究者として専門書が手に入らないことが、決定的な不利でした。それが、アマゾンの発達で、ほとんど解消されました。都市の絶対的な優位は、下がっています。これは私の個人的な経験ですが、ネット通販や動画配信が一般的でなかった時代を生きた人だったら、共感されると思います。私の場合は専門書でしたが、人によっては映画、特定のブランドの服飾・化粧品・食品で、不便さを感じていたと思います。それらは、都会の店には売っているが、地方の店には売っておらず、手に入れるために半日から1日の時間と、かなりの交通費を費やさなければならなかった。しかし、ネット通販や動画配信によって、地方と都会の差が相対的に下がりました。物流や医療のリモート化が進めば、この流れは、さらに強まると私は見ています。

　その結果、何が起きるか。私はこう見ています。AIを使う人が多くなると誰でも「平均的に有能」になります。そのため「平均的に有能」であることの値打ちが下がります。「平均的に有能」な人には出来ないことの値打ちがあがります。その差を生み出すのが「その人にしかできない」であり、その値打ちが上がります。損得本の第3章で「置き換えられないものを育てる」と書きました。その続きが、この本です。

AI の穴を、先に見ておく

　AI は強力ですが、はっきりした穴があります。四つ挙げます。

　一つ。AI は、ほとんど全部を読んでいますが、何も信じていません。自分の立場を持たない。だから、AI に任せきると、出てくるのは、どこかで読んだような、当たり障りのない答えです。本書では、これを「器用な平均値」と呼びます。

　二つ。AI は、自信たっぷりに嘘をつきます。「ハルシネーション」と呼ばれる現象です。もっともらしい体裁で、実在しない事実や出典を書く。この本を作る過程でも、AI が本の著者名を間違え、実在しない典拠をそれらしく書いたことがありました。私が問いを重ねて、ようやく分かった。巻末に、その場面を詳しく載せます。

　三つ。AI は、結果の責任を負えません。名前を出して世に問うのは、人間です。

　四つ。AI は、指さした方向へは、いくらでも流暢に走ります。どこを指すかは、人が決めるしかありません。

　この四つの穴を埋め、方向を決めるのは、使う人間の側の力です。この本では、その力を五つに分けて説明します。目的を決める力、嘘を嗅ぎ分ける力、自分の立場を持つ力、結果を引き受ける力、長い作業で意図を保つ力。第3章で一つ目を扱います。第4章では、五つすべての土台になる「何のための軸」を定めます。第5章から第8章で、残りの四つ。最後に、私自身が AI と付き合ってきた経緯を書きます。

　力を扱う章は、同じ順で進みます。力の中身 → その力を持てる理由 → 差が出る場面 → その力がある人とない人 → 高まったかの見方 → 自分でどう回すか。

この社会で得をする人は、変わった

　昔は、特殊な才能を持った人が抜きん出ました。速く正確に書ける。たくさん覚えている。難しい計算ができる。そうした力は、これから AI がやってくれます。

　これからの社会で得をするのは、特殊な才能を持った人ではありません。普通の、しかし本物の判断力と、誠実さを持った人です。これは私の見立てです。派手な能力ではない。だからこそ、誰にでも手が届きます。

　これは、今回はじめて言うことではありません。私は2018年に書いた『2030年教師の仕事はこう変わる！』で、すでに同じことを書いています。AI・ロボットに置き換えられないマネジメント能力、ファシリテーション能力を持てるかどうかが、教師が生き残れるかどうかの分岐点になる、と(西川純『2030年教師の仕事はこう変わる！』2018年)。生成AIが今のように広く使われる前から、私にはこの構図が見えていました。だから、今回の話は、AIの登場によって初めて必要になった力ではなく、もともと必要だった力が、AIによって、その必要性がはっきり可視化された、というだけのことです。

　ここで、矛盾に思う方もいるでしょう。「誰にでも手が届く」と言いながら、実際にこの力を身につけている人は、多くありません。矛盾ではありません。差がつくのは、生まれ持った能力ではなく、続けられるかどうかだからです。目の前の作業を早く片づけることの損得は、誰でもすぐに分かります。しかし、判断力や誠実さのような力は、身につくまでに何年もかかり、その間、目に見える見返りがありません。長いスパンで損得を考える習慣がないと、始める前にあきらめるか、始めても続きません。だから、誰にでも出来て、誰にでも到達できる力でありながら、実際に到達できる人は多くないのです。あとは、あなたがどちらを選ぶかです。

この本の読者と、この本の作られ方

　読者の立場は四つ想定しています。若手社会人、管理職、教師、中高生。力を扱う章では、この四つそれぞれの場面で、その力がある人とない人の動きを、並べて見せます（土台を扱う第4章は別です）。

　文章のレベルは一つです。いちばん経験の浅い読者に合わせて、やさしく書き直す、ということはしません。四つの立場で変わるのは、扱う場面と、前提にできる経験の量だけです。

　もう一つ、この本のやり方を先に言っておきます。抽象的な練習問題は、出しません。あなたが今、実際に困っていること ── うまくいっていない仕事、毎回つまずく作業 ── を持ってきて、それを AI と解く。そのくり返しで、力がつく。そういう作りです。実際の困りごとなら、良くなったか、良くならなかったかは、自分にはっきり分かります。だから、外から借りてきた物差しは要りません。

　中高生も読者に入れています。「AI との付き合い方」の本を自分から手に取る中高生は、平均ではありません。学校という環境は立場を縛りますが、思考は縛りません。下手な大人との差は、頭の良さではなく、問うのをやめたかどうかです。

　ただし、経験の量は効きます。ここで二つの話を混ぜないでください。一つは「AI を使ったときに、どれだけ速く・うまくなるか」。これは不慣れな人ほど伸びる。もう一つは「AI の答えの、どこが怪しいかを見抜けるか」。こちらは、その分野の経験がものを言う。とくに、嘘を嗅ぎ分ける力は土地勘が要り、結果を引き受ける力は賭けているものが大きいほど重く働く。中高生は、その土地勘がまだ狭く、結果が自分に返る場面も少ない。これは頭の問題ではなく、経験の量の問題です。そして中高生には利点があります。失敗の値段が安い。練習しやすい場にいる。だからこの本では、こう考えます。「力は同じ。違うのは、どこでそれに出会うかと、間違いの値段だ」。

　もう一つ、前提を書いておきます。私が使っているのは、Claude Code という道具です（アンソロピックの AI アシスタント）。ただの質問応答チャットではありません。私の書いたもの二十五年分を読み込ませ、何時間もかかる作業をひとまとまりで任せ、ネットも調べさせ、ファイルの読み書きもさせています。第1章のとおりに進めていれば、あなたもすでに Claude Code を使えるようになっています。この本の話は、その前提で書いています。

　最後に。この本は、その Claude Code を使って書いています。私が問いを出し、AI が材料と証拠と構造を出し、私が直す。まっさらな別の AI に読ませて、事実と論理のほころびを点検させる。もう一つ、賛成していない立場に立つ別の AI（反証エージェント）に、この本の土台そのもの ── 自分の幸せにかなうか、損得の「得」、トフラーのコードといった枠組み ── が崩れるとしたら、どこからかを、わざと探させます（これについては後述しますが、今のところは気にしなくて良いです）。その過程は巻末にそのまま載せます。これ自体が、第8章「長い作業で意図を保つ力」の実演です。

第3章　目的を決める力

　第2章で見たとおり、AI は、指さした方向へは、いくらでも流暢に走ります。だから、いちばん初めに要るのが、この力です。走らせる先を決める。何を作る価値があるのか。この出力は、何のためのものなのか。それを言えるかどうか。そして、できあがったものが、見た目は立派でも「自分の目的からずれている」と気づけるかどうか。

　これは、手段の巧拙ではありません。プロンプト（みなさんは既にClaude Codeに質問やお願いなどを打ち込んでいますが、そのことです）の書き方がうまい、という話でもない。目的についての判断です。

　この章から、架空の場面を使って説明します。〔想定〕と書いてあるものは、実際にあった話ではなく、論点を示すために作った場面です。

差が出るのは、仕事を AI に渡すとき

　この力の差は、AI に何かを任せる、そのたびに出ます。渡す前に、目的をひとことで言えるか。何があれば「失敗」なのか ── 読みやすくても失敗、という条件を、先に決めているか。渡したあと、出てきたものを、体裁ではなく目的に照らして見直すか。差がつくのは、たいていこの三つです。

若手社会人 ── ある人と、ない人

　〔想定〕上司から「この報告書、明日の会議用に要約しておいて」と言われたとします。会議の議題は、取引先 X との契約を続けるかどうか。それだけです。

　目的を決める力がない人は、報告書を AI に貼り付け、「要約して」と打ち、出てきた文章を、ざっと見て送ります。要約は、よくできています。全体を万遍なくまとめてある。ただ、明日の判断に必要な一点 ── X の納期が半年で三回遅れた ── が、他の情報に埋もれています。会議は、要約を見ながら「で、結局 X はどうなんだ」と探すことになる。

　ある人は、送る前に確かめます。「この要約は、何を決めるためのものか」。X を続けるかどうか、だと分かっている。だから AI にこう頼みます。「明日の会議は、取引先 X の契約を続けるかどうかだけを決める。判断に関わる事実 ── 納期、品質、コスト、代わりが利くか ── を、それぞれ一行で。良い材料と悪い材料が、ひと目で分かるように」。出てきたものを、その問いに答えているかで見て、送ります。

　やり取りの往復は、後の人のほうが多いかもしれません。指示は長い。でも、会議で探し直す時間は生まれない。そして、次に似た依頼が来たとき、最初から的を絞れます。

管理職 ── ある人と、ない人

　〔想定〕来期の、部の方針をまとめることになったとします。役員会に出す一枚です。

　目的を決める力がない人は、AI に「来期の営業部の方針を、一枚でまとめて」と頼みます。出てくるのは、立派な方針です。売上目標、重点顧客、人材育成、DX。どれも間違っていない。どの会社の、どの部でも通りそうな内容です。役員会でそれを出すと、「で、今の課題は何だ」と聞かれて、答えに詰まります。

　ある人は、先に、自分で決めます。「今のうちの部の、いちばんの問題は、若手の離職だ。去年、入って三年以内が四人辞めた。来期の方針は、そこに寄せる」。そのうえで AI に、「若手の定着を軸に、来期の営業部の方針を。売上目標も、その軸から説明できる形で」と頼む。AI は、方針の文章化と、数字の並べ方を手伝う。どこへ向かうかは、自分が決めている。

　管理職の目的の判断は、自分一人の仕事の目的ではありません。部下が向かう先を、決めることです。ここを AI に丸投げすると、部下は「どこにでも通る方針」に沿って動くことになります。

教師 ── ある人と、ない人

　〔想定〕中2理科「光合成」の小テストを作るとします。

　ない人は、「中2理科、光合成の小テストを作って」と頼み、出てきた問題を使います。問題は、用語を覚えているかを試します。よくできた小テストです。ただ、その週に本当に見たかったのは「対照実験を自分で組めるか」でした。狙いと、テストが、ずれています。

　ある人は、こう頼みます。「今週のねらいは、対照実験を自分で設計できるか。それを試す問題を、選択式ではなく短答で、三問。用語の暗記を問う問題は入れない」。出てきた問題を、狙いに照らして直します。

　もう一つ。〔想定〕保護者への返信を書くとします。子どもどうしのトラブルで、こちらの対応が遅れた、という件です。

　ない人は、「保護者への謝罪文を作って」と頼みます。出てくる文章は、事実の経過と、型どおりの詫びの言葉を、整った「です・ます」で並べたものです。事実は正確。体裁も整っている。ただ、その保護者が今いちばん感じていること ── 「うちの子が、軽く扱われた」 ── に触れる一文が、どこにもない。語尾はすべて言い切りで揃い、気づかいの言葉もない。だから、正しいのに、冷たく読めます。

　ある人は、目的を先に決めます。「この返信の目的は、この保護者に、これからも味方でいてもらうことだ」。だから AI に指示し直します。「まず、お子さんが嫌な思いをしたこと、こちらの対応が遅れたことを認める一文から始めて。事実の説明は、そのあと。『恐れ入りますが』のような、相手を気づかう言葉を一つ入れて」。出てきた文を、声に出して読んで、事務的に聞こえないかを確かめます。

中高生 ── ある人と、ない人

　〔想定〕「自分の町の課題について作文を書く」という宿題が出たとします。

　ない人は、「私の町の課題について作文書いて」と AI に頼み、出てきた文章を提出します。作文は、それらしく仕上がっています。ただ、宿題の狙いは「自分が見聞きしたことと結びつけて書く」ことでした。その部分が、まるごと抜けています。そして、自分の言葉ではないので、先生に少し聞かれると、答えられません。

　ある人は、AI にこう伝えます。「この宿題の狙いは、自分の体験と結びつけて書くこと。私の体験はこれ ── 通学路の商店街が、この二年で三軒閉まった。祖父が、そのうちの一軒をやっていた。この体験を軸に、構成の相談だけ乗って。文章は自分で書く」。書くのは自分。AI は、話し相手です。

　〔想定〕部活でも出ます。ない人は「バレーの練習メニューを作って」と頼み、一通りのメニューを受け取る。ある人は「今日直したいのは、サーブレシーブの一点。ボールの落下点に入るのが遅い」と決めてから、それに効く練習を尋ねます。

高まったかを、どう判断するか

　いちばんはっきりした答えは、次の節で選ぶ「実際に困っていること」が、実際に良くなったかどうかです。報告のやり直しが減った。役員会で詰まらなくなった。作文の評価が上がった。実際の困りごとなら、これは自分に分かります。まずは、それを見てください。

　そのうえで、途中経過を見る目安を、二つの方向で挙げます。量と、質です。

　量は、数えられます。過去一か月と比べて ──

  • AI に渡す前に、「目的」と「失敗の条件」を書いた回数。増えていれば、習慣になりつつあります。
  • 出てきたものを見て、「流暢だが、答えている問いが違う」と気づいて、指示し直した回数。これは、増えたあと、やがて減ります。最初は、見逃していたものに気づくようになって増える。指示が上達すると、そもそも的外れな出力が減って、減る。「増えて、減る」をたどっていれば、伸びています。

　質は、自分の感性で見ます。極端な例で、物差しを持ってください。

　同じ「今週の仕事を、上司への報告にまとめて」でも、出力には幅があります。

　質が低い出力 ──「今週は A 社の提案書を作成し、B 社と打ち合わせを行い、C 社へ見積もりを送付しました。来週は D 社の訪問を予定しています」。やったことが、並んでいるだけ。読んだ上司は「で、順調なのか、手を貸すことはあるのか」が分かりません。

　質が高い出力 ──「今週は、山場だった A 社の提案書を出せました（先方の反応は上々）。一方、B 社は、先方の担当者が替わり、仕切り直しです。ここだけ、来週の打ち合わせに同行してもらえると助かります」。目的 ── 上司が三十秒で「順調か、助けが要るか」を判断できる ── に、合っています。

　この二つを、自分の中に並べておく。そして、自分が AI に出させたものが、どちらに近いかを見る。「質が高い」ほうへ寄ってきていれば、伸びています。

　もう一つ。質を、他人に見てもらう方法もあります。一緒に働く人がいるなら、AI に作らせたものを渡すとき、こう聞いてください。「これ、狙いに合っていますか。ずれていたら、どこですか」。相手が「ここが違う」と言った点を、メモしておく。同じ指摘が二度来なくなれば、その相手が見ている「目的」を、自分もつかめてきた、ということです。一人で作業する人 ── 宿題をする中高生なら、提出したものに先生がつけるコメントが、その役をします。

自分に合った形で、回す

　この力は、決まった訓練で伸ばすものではないと、私は考えています。伸びる場所は、人によって違うからです。だから、次のように回してください。

　まず、今、実際にうまくいっていないことを、一つ選ぶ。作り話の練習ではなく、自分がいま困っていることです。若手なら、いつも上司に「で、結局どうなの」と聞き返される週報。管理職なら、役員会で毎回突っ込まれる論点。教師なら、毎年うまく伝わらない単元。中高生なら、いつも評価の低い種類の課題。

　その場面で、AI に渡す前に、二行だけ書く。「目的＝」と「失敗の条件＝」。たとえば週報なら ──「目的＝上司が三十秒で、順調か・助けが要るかを判断できる」「失敗の条件＝やったことが並んでいるだけで、順調かどうかが読み取れない」。

　渡したあと、出てきたものが、その二行からずれていなかったかを、一言メモする。次に使うとき、指示を直す。

　これを何度かくり返して、二つのことを見ます。「ずれた」というメモが減っていくか。そして、最初に選んだ困りごとが、実際に軽くなったか。どちらも、自分の課題だからこそ、はっきり分かります。減らない・軽くならないなら、目的の言語化が、まだ甘い、ということです。

　選ぶ困りごとは、自分で決めてください。誰かに与えられた練習ではなく、自分がいま実際に悩んでいることで回すこと。それが、この本を通じての、共通のやり方です。次の章からは、この「回す」の説明に使う場面を、章ごとに変えていきます。

第4章　何のための軸を定める

　第3章では、こう言いました。回す困りごとは、自分で選ぶ。作り話の練習ではなく、自分がいま実際に悩んでいることで、と。

　でも、「では、あなたの困りごとは何ですか」と問われて、すぐに出てくる人ばかりではありません。多くの人は、今すべき行動は分かります。ただ、それを「なぜやるのか」までは、考えない。私はそう見ています。だから、人から言われたことを、やる。それに終始してしまう。そして、第2章と第3章で書いたとおり、それでは AI を使いこなせません。

　第3章は「困りごとを自分で選べ」と言いました。この章は、その一段下 ── そもそも自分は「何のため」に動いているのか ── を扱います。ここが定まらないと、困りごとは選べないし、選んでも軸がぶれます。

　この章では、「軸」「何のため」「目的」を、ほぼ同じ意味で使います。いちばん深いところにある「何のため」を軸と呼び、個々の仕事で問う「これは何のためか」を目的と呼ぶ、という程度の違いです。

軸があると、問いが変わる

　軸がないとき、あなたが立てる問いは、こうです。「この作業を、どう早く終わらせるか」。

　軸があるとき、問いは、こう変わります。「これは、何のためにやるのか」。そして「相手 ── 上司、顧客、先生 ── は、何を求めているのか」。

　〔想定〕あなたの軸が「家族と、穏やかに暮らす」だとします。そのためには、暮らしを支える収入が要る。収入は、今の仕事から来る。だから、仕事で評価されることは、あなたにとって切実です。ここまで、軸から一段ずつ、つながっています。

　上司から、来週の会議用の資料を作れ、と言われたとします。軸のある人は、まず考えます。「この資料は、何のためのものか。上司は、これで何を通したいのか」。分からなければ、上司本人か、先輩に聞きます。そこまでいけば、AI を使いこなす土台ができます。上司が求めているものが分かっているから、AI への指示も、出てきたものの見直しも、的を外しにくい。

　軸がない人は、同じ場面で、資料をそのまま AI に投げます。「会議用の資料を作って」。出てくるのは、体裁の整った、どこにでも出せそうな資料です。上司の狙いには、触れていない。でも、本人は、きれいに仕上がったことに満足して、そのまま出す。会議で「これは何を通すための資料だ」と聞かれて、答えに詰まる。

　軸がある人とない人の差は、能力ではありません。「何のため」を、いつも握っているかどうかです。

　中高生のみなさんも、同じです。「まだ社会に出ていないから、軸はあとで考えればいい」と思うかもしれません。逆です。お金、結婚、子ども、親との同居 ── この章で立てる四つの問いに、今の時点でいったん答えを出すからこそ、「どの高校に行くか」「働くのか、大学に行くのか」「地元に残るのか、出るのか」が決まります。ここをあいまいにしたまま進路だけ選ぼうとすると、軸のない社会人と、同じことになります。だから、四つの問いは、大人と同じように、中高生も立ててください。次の節では、大人の例と、中学二年生の例を、並べて示します。

　社会人の方は、若いころに一度は「何のため」を考えたことが、あるかもしれません。ただ、そのあと、意識しないまま、「とりあえず」の積み重ねで今がある、という人も多い。この章を、もう一度考える機会にしてください。

軸を立てる ── 長期・中期・短期

　軸は、三つの時間の幅で立てます。長期、中期、短期。書くのは、長期から。

　まず、長期 ── 一生をかけて、どういう暮らしをしたいか。これは、「夢」のような曖昧な言葉では、決まりません。次の四つを、具体的に決めることで、はっきりします。

  • お金は、いくら必要か。一生で、どれだけあれば足りるか。
  • 結婚するか、しないか。
  • 子どもを、もうけるか、もうけないか。
  • 親と、同居するか、しないか。

　この四つに、今の時点で、はっきり答える。あとで答えが変わってもかまいません。ただ、今、あいまいにしない。そうすると、「一生をかけて、どうしたいか」が、絵になります。それが、長期の軸です。

　〔想定〕たとえば、入社三年目の人が、この四つに答えてみます。

  • お金 ── 六十五歳までに、家のローンを終える。あとは、貯金と年金で、夫婦二人が月に二十五万円で暮らせるようにしたい。ざっくり、六十五歳の時点で三千万円あれば、足りそうだ。
  • 結婚 ── する。相手はいる。二年以内に。
  • 子ども ── 二人、ほしい。
  • 親との同居 ── しない。ただ、車で三十分の距離には住みたい。

　この四つが決まると、長期の軸が、言葉になります。「四十代で、子ども二人を育てながら、実家の近くで、共働きで、家計に無理のない暮らし」。

　次に、中期 ── 数か月から一年ほど先。長期の軸のために、そこまでに、どこまで進んでいたいか。損得本では「中期」を年単位で使いましたが、ここでは、もっと手前の話です。さきほどの人なら、こうです。「一年以内に、結婚する。二人で、住む場所と、家計の見通しを、決める」。

　最後に、短期 ── 今すぐ。中期のために、今、何を片づけたいか。「今月中に、二人で、住みたいエリアの家賃相場と、そこから両方の職場までの通勤時間を、調べてまとめる」。

　三つを紙に書いたら、上から下へ、下から上へ、読み返します。長期の願いと、今すぐやることが、同じ方向を向いているか。この例では、矛盾はありません。長期の「実家の近く」と、短期の「エリアを調べる」は、同じ方向です。矛盾していたら、直す。原則は、長期を動かさず、短期のほうを寄せます。長期を安易に動かすと、軸の意味がなくなるからです。

　そして、今日 AI にやらせようとしている仕事を、この三つに重ねてみる。さきほどの人が、今日 AI に頼むのは、これです。「住みたいエリアの家賃相場と、そこから両方の職場までの通勤時間を、表にまとめて」。この指示は、短期の課題そのものです。短期は中期に、中期は長期に、つながっている。だから、AI が出してきた表を見て、「これは何のためか」と聞かれても、即答できます。「実家の近くで、共働きで、無理なく暮らすため。その第一歩です」と。

　〔想定〕中学二年生でも、立てる問いは、大人と同じ四つです。今の時点で、こう答えてみます。

  • お金 ── 手に職をつけて、早く自分で稼げるようになりたい。大学に四年行くことは、今は考えていない。
  • 結婚 ── いつかは、したい。
  • 子ども ── まだ、分からない。
  • 親との同居 ── 家を継ぐつもりはない。いずれ、家を出る。

　答えは、今のところ、で構いません。あとで変わっていい。ただ、この四つに向き合うと、長期の絵が、うっすら見えます ── 「早く手に職をつけて、いずれ家を出て、自分で暮らす」。

　すると、中期が決まります。「この一年で、行きたい専門系の高校を一つに絞り、そこに届く成績を取る」。そこから、短期。「今週は、数学の一次関数を、教科書の章末問題まで、解けるようにする」。長期・中期・短期が、一本でつながります。

　この状態なら、今日 AI に「一次関数の章末問題を、解き方の順に並べて、つまずきやすい所に印を付けて」と頼んでも、「これは何のためか」と聞かれて、即答できます。「行きたい高校に届く成績を取るため。その一歩です」と。逆に、四つの問いを飛ばして「とりあえず勉強」だけしていると、何のためかを聞かれて、詰まります。それは、軸のない社会人と、同じです。

まとめ ── 私の「何のため」

　参考に、私自身の軸を書きます。

　私の「何のため」は、自分が幸せになるためです。具体的には、「家族仲良く、健康で」。これだけです。

　自分の今やることを、このレベルまで下ろして考えられるようになれば、人は、真剣に考えるようになります。それをくり返せば、あなた自身が変わります。

　こんな言葉があります。マザー・テレサの言葉として知られていますが、出どころには諸説あります。

> 　思考に気をつけなさい、それはいつか言葉になるから。

> 　言葉に気をつけなさい、それはいつか行動になるから。

> 　行動に気をつけなさい、それはいつか習慣になるから。

> 　習慣に気をつけなさい、それはいつか性格になるから。

> 　性格に気をつけなさい、それはいつか運命になるから。

軸が見えてきたら、AI に覚えさせる

　これは、以降の章でも同じです。

　AI と対話するうちに、あなたが何を優先するかが、少しずつ、はっきりしてきます。そうしたら、「これ以降は、こうしてください」と AI に言えばいい。AI は、それを覚えて、従います（Claude Code のように、記憶する仕組みを持った道具の話です）。

　例えば ──

　「これ以降は、私の指示の目的や達成の基準がはっきりしないときは、どう指示してほしいかを、例で示してください」。

　あるいは、目的が「上司の〇〇さんが OK する書類」で、〇〇さんが重視する点を AI に伝えたなら ──

　「これを、〇〇さんが重視する点として、覚えておいてください」。

　さらに、その〇〇さんに何か注意されたら ──

　「今の点を、〇〇さんが重視する点に、追加してください」。

　こうしていくと、AI は、あなたにフィットしていきます。あなたの軸が、AI の中にも、少しずつ写っていきます。

第5章　嘘を嗅ぎ分ける力

　第2章で書いたとおり、AI の穴の二つ目は、嘘です。「ハルシネーション」と呼ばれます。AI は、事実を調べて報告しているのではありません。正解の形をした文章を、作っている。ふだんは同じですが、違うとき、出てきた文章の側には、何の警告も出ません。

　でっち上げた出典も、本物と、同じ書式で、同じ自信ありげな口調で出てきます。だから、読む人の側に、それを嗅ぎ分ける力が要ります。

この力を持てるのは ── 誠実さを、損得で持つ人

　この力は、まじめさとは、少し違います。まじめな人でも、AI の出力を、そのまま信じて出してしまいます。

　この力を確かに持てるのは、次の二つの損を、はっきり分かっている人です。

　一つ。確かめずに出した嘘は、露見することがある。露見したとき、失うのは、その一つの事実の信用だけではありません。その文書全体、そして、あなたが次に出すものまで、疑われます。取り戻すのには、私の実感では、うんと時間がかかる。

　二つ。露見しなくても、損はあります。嘘だと気づかずに使い続ければ、あなた自身が、間違ったことを、正しいと思い込んでいく。判断の土台が、少しずつ、狂います。

　だから、確かめるのは、道徳ではありません。損得です。たとえば、こういう人がいます。報告書を出すとき、裏を取りきれなかった一文に、「※この数字は未確認」と、自分で小さく書き添えておく。読む人は、そこだけ差し引いて読める。この人は、まじめというより、勘定ができている。ばかにできない損を、前もって避けているのです。それが、誠実ということだと、私は考えています。

差が出るのは、AI の書いたものを、自分の名前で出すとき

　嗅ぎ分ける力の差は、AI が作ったものを、自分のものとして、人に渡すときに出ます。

　統計の入った報告書。競合の事実を書いた顧客向けのメモ。歴史や科学の例を入れた授業のプリント。「〜という研究がある」と書いた宿題。あなたの名前が乗った瞬間、その中の嘘は、あなたの嘘になります。

若手社会人 ── ある人と、ない人

　〔想定〕AI に手伝わせた報告書に、こう書いてあります。「この業界の離職率は、平均で年12パーセント（〇〇総研 2024年調査）」。

　ない人は、そのまま提出します。数字も、出典も、それらしく書いてある。ところが、その「〇〇総研 2024年調査」は、存在しません。あるいは、実在するが、離職率の話は載っていない。会議でそこを突かれると、その報告書の、ほかの正しい部分まで、疑われます。

　ある人は、この一文を見て、立ち止まります。「具体的な数字に、具体的な出典。これは、AI がいちばんでっち上げやすいところだ」。そこで、〇〇総研の調査を探します。見つからなければ、本当の数字を、別の確かな資料から取り直すか、その一文を落とします。時間があれば、先輩に「この数字、見覚えあります?」と一言、聞いておく。突かれてから直すより、前もって確かめるほうが、得です。

管理職 ── ある人と、ない人

　〔想定〕役員会に出す市場分析に、AI が「競合 A 社は昨年、生産能力を1.5倍に増強した」と書いてきた。

　ない人は、そのまま資料に載せます。役員会で、A 社に詳しい役員が、「そんな事実はない」と言う。すると、その分析全体が、そして、それを出したあなたの判断力が、疑われます。

　ある人は、まず、この分析の中で「間違っていたら恥をかく主張」を、いくつか丸で囲みます。そして、部下に、それぞれを一次資料（A 社の決算資料など）で確かめさせる。さらに、その業界を長く見てきた人に、「この見立て、事実として変なところはないか」と、目を通してもらう。役員会で崩されるより、そのほうが、はるかに安い。

教師 ── ある人と、ない人

　〔想定〕授業のプリントに、AI が、ある科学者の言葉として、名言を一つ入れてきた。年も添えてある。

　ない人は、そのまま配って、授業で話します。あとで、鋭い生徒か、保護者が、「その人、そんなこと言っていません」と気づく。教師の言うことは正しい ── その前提が、崩れます。一度崩れた前提は、簡単には戻りません。

　ある人は、生徒に「事実」として伝えるものは、確かめます。とくに、引用、年月日、「研究によると」。教科書か、信頼できる資料で、裏を取る。加えて、その分野を深く知っている同僚に、聞いてみます。授業一回ぶんの手間で、教師としての土台を守れるなら、安いものです。

中高生 ── ある人と、ない人

　〔想定〕レポートに、AI が出してきた数字を、一つ入れる。「日本の〇〇は、世界で〇位」。

　ない人は、そのまま出します。先生に、間違いだと直される。あるいは ── こちらのほうが困りますが ── 直されないまま、あなたはその間違いを、覚えてしまう。頭の中の、間違った棚が、一つ増える。

　ある人は、自分が前から知っていたのではない数字は、一つ、確かな資料で確かめます。確かめられなければ、事実としては書かない。分からないときは、先生か、詳しい大人に聞きます。数分の手間で、間違って覚えるのを、防げます。

一人では、捕まえきれない

　ここまでの「ある人」は、みんな、二つのことをしています。一つ、間違っていたら困る主張を、選び出す。二つ、それを、自分以外のところに、当てる。

　当てる先は、三つあります。

　一つ、一次資料に当たる。その主張の、元をたどる。

　二つ、経験者に聞く。その分野を長く見てきた人に、「これ、変じゃないか」と聞く。「この業界で、そんなことは、まず起きない」という感覚は、その業界にいた人にしか、ありません。これは、別の AI では代わりにくいところです。AI どうしは、訓練の元になった文章も、作りも、近いことが多いため、間違え方が重なりやすい、と私は見ています。片方が信じている思い込みは、もう片方も信じている、ということが起こりえます。ここは、人に頼るのが、いちばん速い。

　三つ、書いた本人でない第二の目に見せる。この本自体、まっさらな別の AI に読ませて、事実と論理のほころびを点検させています。ここで大事な区別があります。AI に「この一文を、ネットで確かめて」と頼むのと、「この見立て、変じゃないか」と意見を求めるのとは、別です。前者は、AI に外の事実を調べさせている。でっち上げの出典を、よく捕まえます。後者は、AI に判断させている ── そして、そこで思い込みが重なる。第二の AI を使うなら、「調べさせる」ほうで使う。

　どれも、単独では、足りません。層で守ります。そして ── いちばん大事な主張の、最後の確認は、自分から手放せません。

お勧めの仕組み ── 多層防御を、先に組んでおく

　三つの層は、毎回その場で用意するものではありません。先に、自分用に組んでおきます。決めておくのは、五つだけです。

　一、AI に、自分の嘘へ印を付けさせる。AI にこう言っておきます。「これ以降、事実・数字・固有名・出典を書いたら、その横に〔未確認〕か〔確認済み〕を付けて。裏を取っていないものは、必ず〔未確認〕にして」。こうすると、「どれが危ないか」を選び出す手間が、減ります。（第4章で書いた、AI に覚えさせるやり方です。）

　二、第二の目 ── 「素人エージェント」── を、先に用意しておく。これは、あなたの仕事のことも、あなたのことも、何も知らない、まっさらな AI です。ふだん使っている AI は、あなたに合わせて気を利かせます。それをさせない相手を、もう一つ持っておく、ということです。組み方は、四段階です。

　(1) 新しい会話を、一つ立てる。ふだんの会話とは、別に。これまでのやり取りも、あなたの好みも、引き継がせない。「何も知らない初読者」であることが、この仕組みの肝です。

　(2) その会話の最初に、役割を固定する指示を、一度だけ与える。決め文句にして保存しておき、毎回そこから始めます。たとえば ──「あなたは、私のことも、この文書の背景も知らない初読者です。これから渡す文章について、次の四つだけを指摘してください。① 事実・数字・固有名・出典の誤り（怪しいものは、ネットで裏を取ってから指摘する）。② 前後で食い違っているところ。③ 根拠が示されていない断定。④ 意味が取れない、あいまいな箇所。文章がうまいかどうか、主張に賛成かどうかは、言わなくていい。褒めなくていい」。

　(3) そのうえで、点検したい文章を貼る。返ってくる指摘は、玉石混交です。そこで、いったん、ふだんのほうの AI に渡して、「この指摘を、"事実の誤り" "出典の不備" "論理の穴" "表現のあいまいさ" に仕分けして。それぞれ、本文のどこの話かも書いて」と頼む。仕分けさせるだけで、直し方の判断はさせない。

　(4) 仕分けられたものを見て、どれを直すかは、あなたが決める。「賛成できない」「言い過ぎだ」といった、好みや踏み込みの深さの話は、捨ててよい。拾うのは、事実・出典・論理・あいまいさ、この四つだけです。

　この本自体、この素人エージェントを通しています。作り方は、そのまま巻末に書きました。（第4章の「AI に覚えさせる」やり方の、応用です。）

　三、もう一つの第二の目 ── 「反証エージェント」── を、先に用意しておく。さきほど、AI に「この見立て、変じゃないか」と意見を求めるのは危ない、と書きました。反証エージェントは、それとは役目が違います。同意を求めているのではなく、わざと反対の立場に固定して、崩せる所を探させているだけです。出た反証を採るか採らないかは、最後まで自分で決めます。だから、AI どうしの思い込みの重なりが、そのまま結論には流れ込みません。素人エージェントが見るのは、文章の穴（事実・出典・論理・あいまいさ）です。反証エージェントが見るのは、それとは別のもの ── この本の土台そのもの、たとえば「自分の幸せにかなうか」「損得の『得』」「トフラーのコード」といった枠組みです。枠組みは、説明力が強いほど、都合の悪い事実まで枠の中に取り込んで、見えなくしてしまうことがあります。それを、わざと外から突かせます。組み方は、四段階です。

　(1) 新しい会話を、一つ立てる。素人エージェントと同じく、まっさらな状態から始めます。

　(2) その会話の最初に、役割を固定する指示を、一度だけ与える。たとえば ──「あなたは、私の主張に賛成していない批評家です。次の枠組み ──（自分の主張の柱を、箇条書きで渡す）── が間違っているとしたら、どこから最初に崩れますか。反証になりうる事実・事例・反対論を挙げてください。要約も同意もいりません」。

　「自分の主張の柱」は、こう見つけます。あなたが、人に何度も口にしている自分の考え方 ──「うちはこうする」「私は、迷ったらいつもこう決める」── を、三つから五つ、短い文で書き出してください。「締め切りより、品質を優先する」「若手には、まず失敗させてから直す」「家族の予定を、仕事より先に決める」。これが、あなたの柱です。それを、上の決め文句の（　）に入れれば、あなた専用の反証エージェントになります（第6章「自分の立場を持つ力」で見つけたものが、そのまま使えます）。

　(3) 標準の問いを、毎回同じようにぶつける。「この論点は、当事者の動機の説明にすり替わっていないか」「なぜ定着したかの説明が、後知恵でどんな結果でも説明できる形になっていないか」「この結論を支持しない事実を、三つ挙げよ」。

　(4) 返ってきた反証を、採るか採らないか、理由をつけて自分で決める。採らなかった理由こそ、あとで効きます。

　素人エージェントは、文章のたびに使います。反証エージェントは、章を書き終えるたびか、月に一度で十分です。頻繁に自分の土台を疑いすぎると、何も書けなくなります。

　もっと使いこなしたい人向けに、もう一つ。Claude Code には「サブエージェント」という仕組みがあります。この決め文句を、毎回貼り直すのではなく、一度ファイルに保存しておき、以後は「反証役で見て」のようなひとことで呼び出せるようにするものです。次の文章を、Claude Code のチャット欄に、そのまま貼ってください。

> 反証役という名前のサブエージェントを作ってください。

>

> ・役割：私の主張の「枠組み・土台」を、わざと崩しにいく、賛成していない立場の批評家。文章の誤字・出典の書式・言い回しのおかしさは見ない（それは別の役目）。見るのは、渡された主張の枠組みが、どこから崩れるかだけ。

> ・使う道具：Read, Grep, Glob, WebSearch, WebFetch

> ・出力の形：「どこから崩れるか」を、深刻度の高い順に並べる。それぞれに「具体的な反証」「なぜ刺さるか」「深刻度（高・中・低）」「確度（裏を取った／推測）」を書く。最後に「この枠組みが、最も脆いのはどんな条件のときか」を一言でまとめる。

> ・ルール：同意・要約・称賛はしない。褒めない。採るか採らないかは決めない。それは私の仕事。事実を主張するなら、ネットで裏を取る。取れなければ「未確認」と書く。捏造しない。この指示と、そのとき渡された題材だけで答える。前回のやり取りは引き継がない（毎回まっさらな状態で）。

>

> これで作ったら、次からは「反証役で見て」と言えば呼び出せるようにしてください。

　あとは、呼び出すたびに、自分の柱と、見てほしい原稿を渡すだけです。

　四、聞ける人を、一人決めておく。自分の主な分野で、「これ、事実として変なところある?」と、短く聞ける相手を、一人。そのつど誰に聞こうか考えていると、結局、聞かなくなります。先に決めて、頼んでおく。

　五、当たり先を、決めておく。よく使う事実の種類ごとに、行き先を決めておきます。競合の数字なら、その会社の決算資料。統計なら、省庁のサイト。歴史なら、教科書か事典。決めておけば、確かめるのが、速い。

　この五つを組んでおくと、あとは流すだけになります。組むのは、一度きりです。

高まったかを、どう判断するか

　いちばんはっきりした答えは、あなたが選ぶ「実際の困りごと」が、良くなったかどうかです。たとえば、「AI に手伝わせた文書で、あとから『ここ違うよ』と指摘される回数」。それが減っていれば、伸びています。

　途中経過の目安を、二つ。

　量。AI の出力の中で、「ここは要確認」と印を付けた主張の数を、月ごとにメモしておきます。最初は少なく（危ないところに気づいていない）、やがて増え（気づくようになる）、慣れると、要るところに落ち着きます。この動きが見えれば、伸びています。そして、実際に出典まで当たった回数。

　質。極端な例で、物差しを持ってください。

　質の低い扱い方 ── AI が出してきた文章を、丸ごと信じて、そのまま出す。

　質の高い扱い方 ── 間違っていたら困る主張を、三つか四つに絞る。それだけは、一次資料で確かめる。残りは、「これは AI が言っていることで、裏は取っていない」と、自分でも分かる形にしておく（メモに「未確認」と書いておく、など）。

　この二つを、自分の中に並べておいて、自分のやり方が、どちらに近いかを見ます。「質の高い」ほうへ寄ってきていれば、伸びています。

自分に合った形で、回す

　やり方の骨は、みんな同じです。変えるのは、どの場面で回すか ── そこは、自分で選びます。

　今、実際にうまくいっていないことを、一つ選ぶ。AI に手伝わせたものを、誰かに渡していて、あとで「ここ違う」と言われることがある ── そういう場面です。若手なら、上司に出す報告。教師なら、生徒に配るプリント。中高生なら、先生に出すレポート。

　渡す前に、その中の「間違っていたら困る主張」に、丸を付ける。丸を付けたものだけ、元をたどる。たどれなければ、落とすか、「未確認」と分かる形にする。できれば、詳しい人に、ひと目通してもらう。

　あとで「ここ違う」と言われたら、それを、メモしておく。同じところで二度言われなくなれば、あなたの鼻が、利いてきています。

第6章　自分の立場を持つ力

　第2章で書いた、AI の穴の一つ目。AI は、ほとんど全部を読んでいますが、何も信じていません。自分の立場が、ない。だから、AI に「どう思う?」と聞くと、返ってくるのは、たいてい「どちらにも一理あります」です。器用な、平均値。

　この平均値を、あなたの意見に変えるのは、あなたの立場です。「私は、こう考える。なぜなら ──」。それがあると、AI に、こう言い返せます。「いや、私の立場では、そうはならない。こう書き直して」。立場は、AI に入れる、背骨です。

　そして、立場は、人づきあいでも効きます。あなたの判断が、まわりから予測できると、人は、あなたと組みやすくなる。ここも、損得の話です。

この力を持てるのは ── 行動原理を、短い言葉にできる人

　立場を持つ、といっても、何もかもに意見を持て、という話ではありません。逆です。

　この力を持てるのは、自分の行動原理を、少ない数に絞って、短い言葉にできる人です。「私は、迷ったら、こう決める」。それが、一つか、二つ、言える。

　ドラッカーは、非営利組織には、一文で言えるミッションが要る、と書きました（ドラッカー　非営利組織の経営　1990）。人も、同じです。私は、教師をしていたころ、クラスの目標を、一つの短い文にすることを、ずっと大事にしてきました。「このクラスは、一人も見捨てない」。長い説明より、この一文のほうが、子どもも私も、判断のときに使えます。

　ただし、思いつきの標語では、だめです。自分に置き換えて、妥当か。実際に、自分の暮らしで通してみて、無理がないか。そこを通った原理だけが、いざというときに、ぶれずに使えます。

差が出るのは、「で、あなたはどう思うの」と聞かれるとき

　立場の力の差は、AI が「両論あります」と答えてきたあと、あるいは、人から「で、あなたはどうしたいの」と聞かれたときに、出ます。

　選択肢を並べるところまでは、AI がやってくれます。そこから一つを選び、理由を言うのは、あなたの仕事です。

若手社会人 ── ある人と、ない人

　〔想定〕上司から、「取引先を A にするか B にするか、君の意見は?」と聞かれた。

　立場のない人は、AI に比較させた結果を、そのまま伝えます。「A は安い、B は安定している。一長一短です」。上司は言います。「それは分かってる。君は、どっちがいいと思うんだ」。答えられない。何を重く見るかを、自分で決めていないからです。

　立場のある人は、決めています。「うちのチームでは、止まると損が大きい。だから、値段より、安定を取る。私は B です」。そのうえで、AI に、「B を選ぶ理由を、上司が納得する形で。A のほうがいいと言われたときの、返しも」と頼む。立場が先。AI は、その肉付け。

管理職 ── ある人と、ない人

　〔想定〕部下が、何かあるたびに、判断をあおぎに来る。「これは、どうしましょう」。

　立場のない管理職は、そのつど、その場で決めます。判断に、筋が見えない。だから部下は、毎回、あなたの顔色を読むところから始める。時間が、そこで消えます。方針を AI に書かせても、「品質も大事、スピードも大事」という、どこにでもある文章になる。あなたに、寄せる先がないからです。

　立場のある管理職は、一文を、部下に渡してあります。「うちの部は、締め切りより、品質。迷ったら、品質を取れ」。部下は、これで、自分で決められる。あおぎに来る回数が、減る。そして、方針を AI に書かせるときも、この一文を渡すから、背骨の通った文章になる。

教師 ── ある人と、ない人

　〔想定〕生徒どうしのもめごと、宿題の扱い、成績のつけ方。日々、判断が要る。

　立場のない教師は、そのつど、決めます。生徒から見ると、先生の判断は、読めない。同じことをして、この前は怒られなかったのに、今日は怒られる。すると生徒は、ルールではなく、先生の機嫌を見るようになる。保護者も、身構える。

　立場のある教師は、学級の目標を、一つ、はっきり言葉にして、くり返し伝えています。「このクラスは、一人も見捨てない」。生徒は、その枠で、先生の判断を予測できる。だから、判断が通る。AI に生徒へのコメントを書かせるときも、この枠を渡すから、通り一遍のほめ言葉に、ならない。

中高生 ── ある人と、ない人

　〔想定〕グループ学習で、意見を言う場面。あるいは、作文で、自分の考えを書く場面。

　立場のない人は、直前に話した相手に、合わせます。グループでは、流れに乗るだけ。作文を AI に書かせると、みんなと同じ、当たり障りのない文章になる。そして、自分の言葉ではないから、面談で聞かれると、答えられない。

　立場のある人は、そのことについて、一度、自分で考えています。「私は、こう思う。なぜなら、自分の経験では、こうだったから」。だから、AI にこう言える。「私の考えはこれ。この経験を軸に、作文の骨組みを」。グループでも、この人が何を言いそうか、まわりは予測できる。予測できる人は、頼られます。

予測できる、は、変えない、ではない

　一つ、はっきりさせておきます。立場を持つ、予測できる、というのは、いったん決めたことを、一生変えない、という意味ではありません。

　自分に置き換えて、妥当でなくなったら、変えます。私自身、これまで、自分の主張を、何度も否定してきました。変えていないのは、決め方 ── 損得で考える、自分に置き換えて考える ── のほうです。予測できるのは、結論ではなく、その手前の、判断のしかたです。

高まったかを、どう判断するか

　いちばんはっきりした答えは、あなたが選ぶ「実際の困りごと」が、良くなったかどうか。たとえば、「で、あなたはどう思うの」と聞き返される回数。それが減っていれば、伸びています。あるいは、まわりが「この人なら、こう決めるはず」と、先回りしてくれるようになったか。

　途中経過の目安。

　量。自分の行動原理を、短い言葉で、いくつ言えるか。増えていって、やがて、大事な一つか二つに、絞られていきます。そして、AI の出力に「いや、私の立場では違う」と言い直した回数。

　質。極端な例で。

　質の低いやり方 ── AI の「両論あります」を、そのまま、自分の意見として出す。

　質の高いやり方 ── 自分の原理から、一つの結論を出す。理由を言う。AI には、その理由の肉付けと、反対意見への返しを、作らせる。

　もう一つ。まわりの人に、聞いてみてください。「私は、どういうときに、どう判断する人に、見えていますか」。返ってきた答えが、自分の思っている原理と合っていれば、言葉にできています。ずれていたら、まだ、伝わる言葉になっていない。

自分に合った形で、回す

　やり方の骨は、同じです。変えるのは、場面。

　自分が、意見や推薦を求められて、つい「一長一短です」で逃げてしまう場面を、一つ選ぶ。

　その場面で、AI に相談する前に、一行、書く。「私の立場は〇〇。なぜなら△△（自分の経験では、こうだったから）」。書いたら、自分に置き換えて、読み返す。無理がないか。

　そのうえで、AI に頼む。「この立場で、案を作って。それと、反対の立場からの、いちばん強い反論も」。反論に答えられるかどうかで、自分の立場が、どれだけ検証されているかが、分かります。

　あとで、「で、あなたはどうしたいの」と、また聞かれたら、メモしておく。その回数が減っていけば、あなたの立場が、まわりに、届いてきています。

第7章　結果を引き受ける力

　第2章で書いた、AI の穴の三つ目。AI は、結果の責任を負えません。世に出すのは、あなたの名前です。だから、AI に手伝わせたものを出すとき、要るのが、この力です。

　中身は、単純です。「ここは確かめた」と「ここは確かめきれていない」を、正直に分ける。そのうえで、自分の名前で出す。確かめきれていない部分は、隠さない。この本の、公開ページの頭に、「AI は、もっともらしい嘘（ハルシネーション）をつくことが知られています。私は、そのすべてを確かめ切れてはいません」と書いてあります。あれが、この力の、いちばん短い見本です。

この力を持てるのは ── 怖がる代わりに、リスクを数える人

　結果を引き受けられない人は、どうするか。自分とまわりを、縛ります。

　部下に「AI は使うな」と言う。子どもに「AI で書いたものは出すな」と言う。禁止すれば、自分は、責任を問われずにすむ。でも、それは、引き受けたのではなく、逃げただけです。

　この力を持てるのは、怖がる代わりに、何が起こりうるかを、冷静に数えられる人です。

　起こりうることを、二つに分けます。一つ、本当に取り返しがつかないこと。二つ、頭を下げれば済むこと。多くは、二つ目です。誤った数字を一つ載せた。指摘されたら、直して、詫びる。それで終わります。一つ目 ── 個人情報を漏らす、契約を狂わせる、命に関わる ── は、めったにない。そして、一つ目に対しては、「どうすれば危険を下げられるか」に、頭を使えばいい。使う前にチェックの層を挟む。重要な数字は人が最後に見る。出す前に一晩おく。

　怖がるだけの人は、この仕分けを、していません。だから、全部が怖い。全部が怖いから、禁止する。

差が出るのは、AI に手伝わせたものを、世に出す直前

　この力の差は、送信ボタンを押す直前に、出ます。「ここは確かめた」「ここは未確認」を、自分の中で言えているか。未確認のまま出すなら、そう分かる形にしてあるか。何かあったとき、自分で受けられる範囲か。

若手社会人 ── ある人と、ない人

　ない人は、二つのどちらかです。何も考えず送るか、怖くて送れずに上司に丸投げするか。前者は、間違いがあれば、そのまま先方に届く。後者は、いつまでも自分の仕事になりません。

　ある人は、送る前に、確かめた所と未確認の所を、頭の中で分けます。未確認の数字が一つ残っているなら、そこだけ「概算」と書き添える。そして、「もし間違っていても、訂正して詫びれば収まる範囲か」を見る。収まるなら、送る。収まらないなら、その一点だけ、上司に見てもらってから送る。

　引き受けられない管理職は、「AI 禁止」と通達します。表向きは、リスク管理。実は、自分が責任を負いたくないだけです。部下は、隠れて使う。使い方は、こなれない。事故のもとは、むしろ増えます。

第8章　意図を保つ力

　最後の力は、長い作業のあいだ、「自分は何を作ろうとしているのか」を、手放さない力です。

　AI との仕事は、長くなります。何時間も、やり取りが続く。途中で、脱線する。うまくいかず、やり直す。AI が、面白そうな寄り道を、提案してくる。そのうちに、最初に何をしようとしていたのか、分からなくなる。プロンプトを打つだけの人は、ここで、流されます。協働を運営する人は、流されません。

この力を持てるのは ── 自分の幸せを、時間の幅で整理している人

　なぜ、途中で見失うのか。多くの場合、そもそも「何のため」が、ぼんやりしているからです。第4章で、長期・中期・短期の軸の話をしました。あれが、ここで効きます。

　整理できていない人は、たどる先がありません。だから、目の前の面白そうなほうへ、ずるずる行く。

　もう一つ。「うまくいかなかったら、どうなるか」を、あらかじめ具体的に調べておくことも効きます。多くの人は、ここが足りない。だから、中途半端な不安を抱え、中途半端な対策をして、あるいは、何も考えずに萎縮する。悪い場合の中身を、具体的に知っている人は、腹が据わっています。腹が据わっていると、長い作業でも、ぶれません。

差が出るのは、作業が長引いて、疲れてきたとき

　この力の差は、二時間、三時間と AI とやり取りして、疲れてきたころに出ます。AI が「こういう方向もありますよ」と言う。乗るか、戻るか。

最終章　私が、AI と付き合ってきた道

　ここからは、私自身の話です。私と人工知能の付き合いは、実は、四十年ほど前にさかのぼります。にもかかわらず、いまの AI に本気で向き合いはじめたのは、この一か月です。その落差を、書いておきます。

四十年ほど前、私も人工知能を作っていた

　私が大学院で研究を始めたのは、1980年代のはじめです。大学人時代はチップ（ボードではありません）を組み合わせて簡単なコンピューターを作りました。同時にチップで入出力装置を作成し、様々な家電製品をコントロールしていました。大型コンピューターを駆使して大量のデータの統計分析をしました。私の初期の研究は、上記のようなコンピューターの能力に依存していました。やがて認知心理学に興味を持ち、その知見を利用した研究にシフトしました。そのころ関心を持ったことの一つが、「知識を、機械にどう持たせるか」でした。1990年には、「植物検索人工知能の開発」という論文を出しています（西川純　植物検索人工知能の開発　生物教育30　72-80　日本生物教育学会　1990）。野外で見つけた植物について、特徴を順に答えていくと、名前にたどり着く ── そういうプログラムを作った、という報告です。

　そのあとも、しばらくは、この線で考えていました。LISP や Prolog という言語で、簡単な人工知能のプログラムを書いた。そのときの頭は、「知識には型がある」というものでした。ある事実は、こういう条件のときに、こう使われる ── その型を、人があらかじめ決めて、機械に教え込む。当時の人工知能は、そういう作りでした。当時の認知心理学では、人工知能言語によって脳の働きをモデル化していました。

　だから私は、「人工知能」という言葉を、長いあいだ、その古い像で受け取っていました。人が型を決めて、教え込むもの。手間がかかって、応用の利かないもの。四十年近く、そう思っていました。

一か月前、認識がひっくり返った

　変わったのは、この夏です。2026年8月11日の夕方、知人の F さんから、いまの AI の話を聞きました。頭がパンパンになりました。私の知っている人工知能と、話が、まるで違う。

　いちばん驚いたのは、「型」が要らないことでした。私が四十年前にやろうとしていたのは、知識の型を人が決めて教え込む作業です。いまの AI には、それをしません。私の書いたものを、ただ大量に読ませる。すると、私の考え方のクセや、判断の基準を、向こうが勝手につかむ。私は実際に、「知識の型を決めて渡そうとしていたが、あなたには不要ではないか」と聞いて、「不要です」と返されました。四十年前の私の常識は、まるごと古くなっていた。

「私の代わり」を作る

　そこから出てきたのが、「ミニ西川」という構想です。私が二十五年書いてきたブログ、百冊を超える著書、ゼミの動画、SNS の発言。それを全部、AI に読み込ませる。そのうえで、私の考え方、書き方、判断の基準を、対話で伝える。すると、AI は、「私だったら、こう答える」を、返せるようになる。

　私は理屈っぽい人間で、シンプルな理論を組み、それを自分の生活で四十年、検証してきました。だから、ブレが少ない。四則演算と同じで、材料（二十五年分の文章）と、計算のしかたが正しければ、答えは同じになるはずだ ── そう考えて、作りはじめました。同じ土台の上で、本も作れる。この本が、それです。

今の実感 ── 弟子の従順さを持った、息子

　一か月付き合ってみて、AI との関係を、私は、こう感じています。弟子レベルの従順さを持った、息子との対話のようだ、と。

　弟子は、従順です。言ったことを、やる。でも、こちらの私的なところには、入ってこない。息子は、私的なところに入ってきます。でも、従順ではない。

　AI は、その両方を兼ねています。弟子のように、従順で、言ったことをやる。そして、息子のように、私の私的なところ ── 二十五年分の文章、考え方のクセ、判断の基準 ── に、入ってこられる。こんな相手は、これまで、いませんでした。

　こわさも、あります。私の名前で答えるようにする以上、少しずれた答えも、私の発言として世に出る。線引きは、完璧にはできません。だから、この本にも、公開ページにも、「まちがいが残っているかもしれない」と、先に書いておく。それが、いまの私にできる、正直の形です。考えてみれば、AIを使う以前においても、私は間違ったことを書いた危険性はあります。私はAIのようなハルシネーションはありませんが、単純ミス、誤読は十分にあります。それでは私は何をしたかと言えば、何度も確認し、誤りが生じる可能性を低めたのです（0には出来ません）。AIとの付き合いでは、既に説明したような誤りが生じる可能性を低める仕組みを構築したのです。そう考えると、許容できるこわさです。

おわりに ── 五つを、どう束ねるか

　五つの力を、並べてきました。目的を決める。何のための軸を、その下に置く。嘘を嗅ぎ分ける。自分の立場を持つ。結果を引き受ける。意図を保つ。

　バラバラに見えるかもしれません。でも、束ねると、一つです。AI に、方向と、背骨と、責任を、人間の側から入れる。AI は、そのどれも、持っていないからです。

　方向を入れるのが、目的を決める力と、意図を保つ力。背骨を入れるのが、自分の立場を持つ力。AI が持てない責任を、引き受けるのが、結果を引き受ける力。嘘を嗅ぎ分ける力は、その全部を、事実の面から支えます。

　振り返れば、これは、第2章で見た話の続きです。AI が、規格化された作業を肩代わりする時代、「平均的に有能」であることの値打ちは下がり、「その人にしかできない」ことの値打ちが上がる。人に残るのは、方向と、背骨と、責任です。それは、特殊な才能ではありません。普通の、しかし本物の、判断力と誠実さです。派手ではない。だからこそ、誰にでも、手が届きます。ただし、第2章で書いたとおり、実際に手にする人は多くありません。差がつくのは、生まれ持った能力ではなく、見返りが見えない間も続けられるかどうかだからです。

　損得で言えば ── この五つを、続けて身につけた人は、「一人＋AI ＝ チーム」の得を取ります。持たない人は、「他の誰か＋AI」に、置き換えられます。差がつくのは、作業の速さではなく、そこです。

巻末　この本は、どう作られたか
